# ADR — 아키텍처 결정 기록

macOS 데스크톱 포팅과 **라이브 에이전트 브리지**(MCP로 실행 중인 앱을 직접
조작하는 경로)에 관한 결정을 기록한다. 각 항목은 *무엇을 정했는가*보다
**무엇을 포기했는가**와 **왜 그 대가가 남는 쪽이 나은가**를 남기는 것이 목적이다.

---

## ADR-001 — 데스크톱 셸은 Tauri 유지, SwiftUI 재작성 안 함

**맥락.** "native mac 이냐 Tauri 냐"를 재검토했다. 검토 시점에 Tauri 셸은 이미
존재했다(PR #2 `504bac7`, 보안 픽스 PR #3). 즉 이 결정은 새 선택이 아니라
**기존 선택을 뒤집을 이유가 있는지**의 판단이었다.

**결정.** Tauri 유지.

**근거.** 이 앱의 무게중심은 Fabric.js 캔버스다 — 템플릿 엔진, span 그룹 합성,
하이라이트 loupe, 렌더 파이프라인이 전부 그 위에 있다. SwiftUI/Core Graphics
재작성은 UI 껍데기 교체가 아니라 **제품의 심장 재구현**이고, 같은 캔버스 코드에
물려 있는 헤들리스 렌더·MCP 서버·e2e 스펙까지 동시에 죽는다. 네이티브로 얻는
것(메모리, 기동 속도, 플랫폼 위젯)은 이 제품의 병목이 아니다.

**포기한 것.** 네이티브 텍스트 엔진·접근성 트리, 웹뷰 없는 배포 크기.

**뒤집을 조건.** 캔버스 성능이 실사용에서 병목이 되거나, iPad/Mac 카탈리스트
같은 네이티브 전용 표면이 제품 요구가 될 때.

## ADR-002 — 에이전트 연결은 파일 왕복이 아니라 라이브 브리지

**맥락.** 기존 에이전트 경로는 파일 인터페이스였다: MCP가 `.studio.zip`을 패치하고
별도 headless chromium이 렌더한다. 사용자가 보는 앱과 에이전트가 만지는 것이
**서로 다른 사본**이라, 사람이 편집 중인 프로젝트에 에이전트가 손댈 수 없다.

**결정.** 실행 중인 데스크톱 앱의 **살아 있는 프로젝트**를 MCP가 직접 조작한다.
파일 경로는 제거하지 않고 병행 유지한다.

**근거.** 사람이 편집하던 자리에서 에이전트가 이어받는 것이 이 제품에서 AI를 쓰는
실제 방식이다. 파일 경로는 헤들리스 CI와 사람 없는 배치 렌더에 여전히 필요하므로
대체가 아니라 추가다.

**포기한 것.** 앱이 떠 있어야만 동작하는 도구군이 생긴다 — `live_*` 도구는
앱 미실행 시 명시적으로 실패하고 파일 도구를 안내한다.

**대안(기각).** 앱 안에 채팅 사이드바를 넣는 인앱 에이전트. API 키가 앱으로
다시 들어와야 하는데, 이 프로젝트는 `928086e`에서 **인앱 LLM 호출과 API 키 없음**을
명시적 설계 원칙으로 걷어낸 적이 있다. 그 결정을 되돌릴 이유가 없다.

## ADR-003 — 전송은 루프백 HTTP가 아니라 유닉스 도메인 소켓 + NDJSON

**맥락.** MCP 서버(Node)가 앱(Rust/웹뷰)에 말을 걸어야 한다. 통상적 선택은
`127.0.0.1:<port>` + 베어러 토큰이다.

**결정.** `app_config_dir()/agent-bridge.sock` 위의 **개행 구분 JSON**.
소켓 파일 모드 0600, 부모 디렉터리 0700이 접근 제어의 전부다(토큰 없음).

**근거.**
1. **브라우저는 유닉스 소켓에 연결할 수 없다.** 로컬 HTTP 포트를 여는 순간
   딸려오는 localhost CSRF / DNS 리바인딩 공격군이 통째로 사라진다. 파일을 쓸 수
   있는 데스크톱 앱에서 이 차이는 작지 않다.
2. **파일 권한이 정확히 맞는 접근 제어 모델이다.** 원하는 정책은 "이 사용자만"이고,
   0600이 바로 그것이다. 토큰은 결국 같은 사용자만 읽을 수 있는 파일에 두게 되므로
   실질 보안은 동등한데 상태와 코드만 늘어난다.
3. **포트 충돌·스쿼팅이 없다.** 경로가 곧 주소다.
4. **의존성 0개.** 클라이언트가 MCP 서버 하나뿐이라 라우팅·미들웨어·콘텐츠 협상이
   필요 없다. HTTP를 쓰면 axum/hyper 트리를 다시 끌어와야 하는데(0단계에서
   `plugin-http`와 함께 507줄이 빠졌다), NDJSON은 이미 잠겨 있는 `tokio`의
   feature만 켜면 된다.

**포기한 것.** 이식성(Windows는 named pipe가 필요). 현재 타깃이 macOS 전용이므로
지금 비용을 치를 이유가 없다. `curl`로 찔러보는 편의도 잃는다.

## ADR-004 — Rust는 소켓을 소유하고, 데이터는 웹뷰가 소유한다

**맥락.** 프로젝트 상태는 웹뷰의 Zustand 스토어에 있다. Rust는 프로젝트를 모른다.

**결정.** Rust는 요청을 `bridge:request` 이벤트로 웹뷰에 넘기고 oneshot에 재운다.
웹뷰가 `bridge_respond` 커맨드로 답하면 그 값이 소켓으로 나간다.

**근거.** 대안은 프로젝트 모델을 Rust에 복제하는 것인데, 그 순간 **진실의 원천이
둘**이 되고 타입/마이그레이션을 이중 관리해야 한다. 브리지는 배관이지 도메인이
아니다.

**세부.**
- `bridge_ready` 핸드셰이크: 웹뷰가 리스너를 걸기 전에 온 요청은 120초를 기다리는
  대신 즉시 "editor window is not ready yet"으로 실패한다.
- 죽은 소켓 파일 처리: 크래시하면 소켓 파일이 남아 `bind`가 EADDRINUSE로 실패한다.
  지우기 전에 **연결을 먼저 시도**해서, 살아 있는 인스턴스의 소켓을 두 번째
  인스턴스가 훔치지 않게 한다.
- 종료 시 소켓 파일 정리는 하지 않는다. 위 bind 로직이 이미 유일한 실패 모드를
  덮으므로, `RunEvent` 훅을 더하는 것은 코드만 늘린다.

## ADR-005 — 명령 어휘는 `applyPatch`를 그대로 재사용

**결정.** 라이브 패치는 파일 기반 CLI가 쓰는 `src/lib/projectPatch.ts`의
`applyPatch(project, ops)`를 **그대로** 통과한다. 새 명령 체계를 만들지 않는다.

**근거.** `applyPatch`는 이미 순수 함수이고, `id`/`imageKey`/`spanGroupId` 같은
위험 필드를 거부하고, span follower의 leader 소유 경로를 막고, 클램프와 거절을
`issues[]`로 돌려준다. 브리지가 별도 어휘를 만들면 **이 화이트리스트를 두 번
관리**하게 되고, 둘이 어긋나는 날 라이브 경로가 더 허술한 쪽이 된다.
`live_inspect`가 `inspectBundle`을 재사용하는 것도 같은 이유다 — 번들을 읽든
살아 있는 앱을 읽든 에이전트가 보는 어휘는 하나여야 한다.

**예외는 화면 이동뿐.** `focus`(MCP `live_focus`)는 step과 활성 슬라이드만 바꾸는
별도 메서드로 두었다. 프로젝트 데이터를 하나도 건드리지 않으므로 `applyPatch`의
화이트리스트가 지켜야 할 것이 없고, 반대로 patch op으로 만들면 "데이터를 바꾸지
않는 op"이라는 예외를 어휘 안에 들여오게 된다. 이 메서드가 없으면 에이전트는 앱이
step 1에 있을 때 에디터로 갈 방법이 없어 사용자가 직접 클릭해야 했다.

**알려진 한계.** 이미지 파일을 새로 들여오는 op(`file` 필드)는 라이브에서
지원하지 않는다. 웹뷰에는 파일시스템 접근이 없어 blob을 IndexedDB에 넣을 수 없다.
`live_patch`는 이 경우 명시적으로 거절하고 `patch_bundle`을 안내한다.

## ADR-006 — 라이브 패치는 `loadProject`가 아니라 `updateProject`

**맥락.** `loadProject`는 `step`을 2로 되돌리고 `activeSlideId`를 첫 슬라이드로
리셋한다.

**결정.** 라이브 패치는 `updateProject(next)`로 프로젝트를 제자리 교체한다.

**근거.** 사용자가 5번 슬라이드를 편집하는 중에 에이전트 패치가 화면을 1번으로
낚아채면 협업이 아니라 방해다. `updateProject`는 step과 선택 슬라이드를 보존하면서
`updatedAt`만 갱신한다. 캔버스는 `FabricCanvas`의 시드 effect가 `[activeSlide, …]`에
걸려 있어, 새 슬라이드 객체가 들어오면 **기존 경로 그대로** 다시 그려진다 —
브리지를 위한 렌더 코드는 한 줄도 필요 없었다.

## ADR-007 — `live_view`는 풀 해상도로 렌더하고 MCP 층에서 축소

**결정.** 웹뷰는 export와 동일한 전체 해상도로 렌더하고, 축소는 MCP 서버가
(`view_output`과 같은 `sips` 경로로) 한다.

**근거.** `renderSlide`에는 `previewWidth`가 있지만, 절대 픽셀 상수(fit-to-box
하한, 헤드라인 갭) 때문에 프리뷰 스케일과 export 스케일의 레이아웃이 **미묘하게
갈린다**(`ExportPanel`에 같은 이유의 주석이 이미 있다). 레이아웃을 판단하는
에이전트에게 실제로 출고되는 것과 다른 그림을 보여주는 것은 정확히 틀린 절충이다.
페이로드가 커지는 대가는 로컬 유닉스 소켓에서 무시할 만하다.

## ADR-008 — 브리지를 열기 전에 Keychain/HTTP 표면 제거

**맥락.** `928086e`가 인앱 번역과 API 키를 걷어낸 뒤에도 데스크톱 셸에는 그
배관이 남아 있었다: `keychainStorage`(호출부는 자기 테스트뿐), Rust `keychain_*`
커맨드 3개, `tauri-plugin-http`, CSP `connect-src`의 LLM 호스트 3곳,
capability의 http 허용목록.

**결정.** 브리지 작업 전에 먼저 제거했다(커밋 `8b2d5e5`).

**근거.** 에이전트가 붙는 로컬 리스너를 여는 마당에, 쓰지도 않는 네트워크 도달
범위를 상속시킬 이유가 없다. 죽은 코드는 리뷰 때 "쓰이는 것"처럼 보인다는 점에서
그 자체로 보안 부채다.

## ADR-009 — dirty는 플래그가 아니라 해시 비교, `updatedAt` 제외

**맥락.** 문서 모델에는 "파일과 다른가"라는 상태가 필요하다. 통상적 선택은
편집마다 세우고 저장마다 내리는 불린 플래그다.

**결정.** `hash(project) !== savedHash`. FNV-1a 10줄, 의존성 없음.
**`updatedAt`은 해시에서 뺀다.**

**근거.** 플래그를 내려야 하는 경로가 하나가 아니다 — undo, 에이전트 브리지 패치,
일괄 편집이 전부 스토어를 우회하지 않고 지나가고, 그 중 하나라도 빠뜨리면
"저장했는데 dirty" 또는 그 반대가 된다. 비교는 그 목록을 없앤다: **저장 시점까지
undo 하면 dirty가 스스로 풀린다.** `updatedAt`을 빼는 건 선택이 아니라 필수다 —
스토어의 모든 쓰기가 새 타임스탬프를 찍으므로, 포함하면 undo 로 되돌린 프로젝트가
영원히 dirty로 남아 이 설계의 목적 자체가 무너진다.

**포기한 것.** 키 순서가 달라지면 false dirty. 안전한 방향이라 수용한다.
32비트 충돌은 "불필요한 저장 한 번"으로 나타나고, 미러가 그 구간을 덮는다.

## ADR-010 — 종료 가드의 3초는 결정 시한이 아니라 **생존 확인**

**맥락.** dirty 상태의 종료를 붙잡아 물어보려면 Rust가 `prevent_close()`를 걸고
웹뷰의 답을 기다려야 한다. 웹뷰가 먹통이면 앱이 종료 불가가 된다.

**결정.** 웹뷰는 `close_ack`로 **살아 있음만** 3초 안에 증명한다. ack 이후에는
시한이 없다. ack가 없으면 종료를 허용한다.

**근거.** 3초를 *결정* 시한으로 두면 두 가지가 동시에 깨진다: 사용자가 프롬프트를
읽는 동안 앱이 사라지고, 「저장」을 골라 시작된 10초짜리 저장이 종료에 잘린다.
생존 확인으로 두면 둘 다 사라진다. ack가 안 오는 웹뷰는 어차피 저장할 수 없고,
미러가 작업을 들고 있으므로 **종료 불가로 사용자를 가두는 쪽이 더 나쁘다.**

`generation` 카운터가 붙어 있는 이유: 닫기 → 취소 → 3초 안에 다시 닫기 를 하면
첫 요청의 타이머가 살아서 두 번째를 죽인다.

**포기한 것.** ⌘Q는 `PredefinedMenuItem::quit`이 아니라 커스텀 항목이다 —
macOS의 native quit은 창 이벤트를 거치지 않아 가드를 통째로 건너뛴다. Dock 아이콘
우클릭 → 종료 같은 경로는 여전히 가드 밖이고, 미러가 그 구간을 맡는다.

## ADR-011 — 인스턴스 잠금은 `setup()`이 아니라 `build()` **이전**

**맥락.** 두 인스턴스는 하나의 localStorage origin, 하나의 크래시 미러, 그리고
이제 하나의 문서 파일을 공유한다. 브리지는 이미 소켓 충돌로 이를 감지하지만
경고만 남긴다.

**결정.** `tauri::generate_context!()`로 identifier를 얻어 **빌더를 만들기 전에**
`<config>/instance.lock.sock`을 잡는다. 실패하면 `osascript` 경고 후 종료.

**근거.** `setup()`은 늦다. 창 — 그리고 그 웹뷰 — 은 `build()`가 만들기 때문에,
setup에서 돌려보내는 시점의 두 번째 사본은 이미 공유 localStorage를 rehydrate
했고, 첫 디바운스 틱에 미러를 덮어쓰며, **자기 keep-set으로 고아 이미지 스윕을
돌린다.** 그게 바로 이 검사가 막으려던 손상이다.

**포기한 것.** 두 곳에서 값을 안다 — `instance.rs`가 macOS의 config 경로 모양
(`~/Library/Application Support/<identifier>`)을 직접 적는다. AppHandle 없이
그 경로를 알 방법이 이것뿐이다. 알림은 Tauri 다이얼로그가 아니라 `osascript`
(`update.rs`가 `curl`을 쓰는 것과 같은 이유: 플러그인은 빌드된 앱을 요구하고,
여기서 앱을 빌드하는 것이 금지된 일이다). 대가는 경고창이 "osascript" 이름으로
뜬다는 것.

## ADR-012 — 백업은 *직전* 버전이 아니라 방금 저장한 바이트를 회전한다

**맥락.** Phase 2는 저장할 때마다 최근 10개를 `<config>/backups/<projectId>/`에
회전 보관한다. "직전 버전"을 넣으려면 덮어쓰기 전에 디스크에서 되읽어야 한다.

**결정.** 이미 메모리에 있는 **방금 저장한 바이트**를 넣는다.

**근거.** 되읽기는 모든 저장의 IO를 두 배로 만든다(번들은 스크린샷 포함 수 MB).
그리고 세는 방식이 달라진다: 직전 버전을 넣으면 10번 저장 후 백업은 9개다.
방금 저장한 것을 넣으면 정확히 10개고, "이 버전 직전"은 목록의 두 번째다 —
UI가 그렇게 보여준다.

**포기한 것.** 가장 새 백업이 현재 파일과 같은 내용이라 한 칸을 중복으로 쓴다.

## ADR-013 — 라이브러리 은퇴는 데스크톱에서만

**맥락.** Phase 2는 `useLibraryStore`(앱 안의 가짜 Finder)를 파일로 대체한다.
하지만 웹 빌드에는 파일이 없다 — 라이브러리가 프로젝트를 여러 개 두는 **유일한**
수단이다.

**결정.** 마이그레이션과 UI 제거를 `isTauri()` 뒤에 둔다. 웹은 그대로 둔다.
스토어 자체는 양쪽 모두에서 한 버전 더 남는다.

**근거.** 전제 1(웹 빌드는 더 이상 쓰지 않되 깨지지만 않으면 된다)과 "새 기능은
`isTauri()` 뒤에"를 그대로 따른 결과다. 파일이 없는 빌드에서 파일로의 마이그레이션은
정의되지 않는다. 부수 효과로 웹 e2e 스펙 112개가 손대지 않고 그대로 통과한다.

**포기한 것.** 한동안 두 빌드의 1단계가 다르게 보인다. 데스크톱은 순수 "새
프로젝트" 폼이고, 웹은 여전히 라이브러리 목록과 파일 열기를 겸한다.
