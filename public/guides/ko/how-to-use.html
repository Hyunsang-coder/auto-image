App Store Screenshot Studio 사용법

시뮬레이터 스크린샷 원본에서 다국어 App Store Connect 제출용 PNG 세트까지, 네 단계면 끝납니다 — 전부 내 Mac 안에서, 계정도 업로드도 없이. AI 어시스턴트가 대부분을 대신해 주는 파일 기반 파이프라인까지 포함한 전체 안내입니다.

1단계 — 프로젝트 시작

스튜디오를 macOS용으로 내려받아 실행하세요 — 첫 화면은 설정 폼이 아니라 런처입니다. 미리 정할 건 없습니다. 기기 종류는 올리는 스크린샷에서 자동 감지되고, 사이즈는 에디터 헤더에서 고릅니다. 빈 화면에서 시작하지 않아도 됩니다:

  • 템플릿에서 시작 — 디자인된 멀티 슬라이드 스타터 세트로 바로 에디터에 진입합니다.
  • 파일 가져오기 — 프로젝트 열기 옆 카드입니다. AI가 작성한 파일 세트(매니페스트 + 캡션 + 스크린샷, 아래 참고)를 선택하면 한 번에 검토만 하면 되는 프로젝트가 만들어집니다.
  • 이미 있는 프로젝트 열기 — .studio.zip 파일을 고르거나 최근 프로젝트에서 바로 엽니다(⌘O). 내 프로젝트는 시작 카드 아래에 썸네일로도 보이고, .studio.zip을 창에 끌어다 놓으면 그 파일을 그대로 엽니다.

어떻게 시작하든 프로젝트는 곧바로 파일이 됩니다. 따로 저장 위치를 고르지 않으면 ~/Documents/Screenshot Studio/에 놓이고, ⌘S·⇧⌘S와 파일 메뉴가 여느 Mac 앱과 똑같이 동작합니다. 창 제목은 파일 이름이고, 저장하지 않은 편집이 있으면 앞에 점이 붙습니다. 스크린샷과 프로젝트는 내 Mac 안에만 있습니다. 네트워크 요청은 실행할 때 새 버전이 있는지 확인하는 것 하나뿐이고, 헤더 ⋯ 메뉴의 시작할 때 확인으로 끌 수 있습니다.

2단계 — 에디터에서 디자인

  • 스크린샷 — 슬라이드당 한 장씩 업로드하면 디바이스 프레임에 자동으로 들어갑니다. 회전, 가장자리 드래그 크롭, 히어로 레이아웃용 캔버스 밖 블리드도 가능합니다.
  • 텍스트 — 슬라이드별 헤드라인·서브헤드라인에 타이포그래피 전체 제어; 드래그로 배치하고 더블클릭으로 편집합니다. 단어를 ==이렇게== 감싸면 그 부분만 강조 스타일로 그려집니다 — 표시가 텍스트 안에 들어 있어 번역을 거쳐도 유지됩니다.
  • 하이라이트 — 스크린샷 위에 점선 영역을 그리면 확대된 루페 카드가 베젤 위에 떠오릅니다.
  • 부가 요소 — 배지(월계관 평점 배지 포함), 스파클·손그림 동그라미·화살표 같은 벡터 장식, 그라디언트/이미지 배경, 슬라이드 두 장에 걸치는 App Store 스타일 2페이지 파노라마.
  • 헤더 ⋯ 메뉴의 템플릿으로 저장은 스크린샷을 뺀 디자인을 시작 화면의 새 카드로 남깁니다.

3단계 — 현지화

캡션은 슬라이드 × 언어 표에 들어 있습니다. 가장 빠른 방법은 MCP 에이전트를 연결해 두고 비어 있는 캡션을 전부 번역해 달라고 하는 것입니다 — 에이전트가 표에 바로 써 넣고, 새 언어도 알아서 추가합니다. 손으로 채우는 방법은 세 가지:

  1. 그리드에 번역을 직접 입력합니다.
  2. 템플릿을 내보내(CSV 또는 JSON, 언어마다 라벨이 붙은 열 하나) 스프레드시트에서 채우거나 번역가에게 넘긴 뒤 다시 가져옵니다. 빈 칸은 건너뛰므로 일부만 채워도 됩니다.
  3. 내장 번역 프롬프트를 복사해 내보낸 템플릿과 함께 ChatGPT / Claude / Gemini에 붙여넣고, 채워진 파일을 다시 가져옵니다. API 키가 필요 없습니다.

앱 UI가 현지화돼 있다면 01-home.en.png, 01-home.ko.png, … 형식의 이름으로 언어별 스크린샷을 한꺼번에 추가하세요 — 앞자리 숫자가 슬라이드를, 확장자 앞 접미사가 로케일을 결정합니다. 오버라이드가 없는 언어는 기본 스크린샷으로 대체됩니다. 에디터의 편집 언어 메뉴에서 언어를 고르면 내보내기 전에 캔버스에서 확인하고, 위치·크기·배경·기기를 그 언어에만 따로 맞출 수 있습니다. 손대지 않은 속성은 공통 레이아웃을 따릅니다. 전체 전략은 현지화 가이드를 참고하세요.

4단계 — 내보내기

클릭 한 번으로 모든 슬라이드 × 언어를 App Store Connect의 정확한 해상도로 렌더링합니다. 알파 채널이 제거돼 업로드가 반려되지 않고, 내가 고른 폴더에 locale/device/NN.png 구조로 저장됩니다. “fastlane 폴더” 버튼은 바로 실행 가능한 fastlane deliver 폴더를 만들어 줍니다 — 번들 ID와 API 키만 넣은 뒤 ./upload.sh를 실행하세요.

AI 에이전트 파이프라인 (클릭 0번)

스튜디오의 입력과 출력이 모두 파일이라서, 위의 모든 과정은 사람이 키보드 앞에 없어도 돌아갑니다. AI 어시스턴트(Claude Code, Cursor 등)가 가져오기 폴더의 초안을 만들면: 

launch-screenshots/
├── manifest.json        # 디바이스, 로케일, 슬라이드별 레이아웃·텍스트 블록 수
├── captions.csv         # 슬라이드 × 언어 캡션 표
├── 01-home.en.png       # 스크린샷: {slide}[-desc].{locale}.{ext}
├── 01-home.ko.png
└── 02-add.en.png

앱에서는 1단계의 파일 가져오기로 그 파일들을 한꺼번에 선택하면 됩니다 — 폴더가 아니라 파일을 고르고, 창에 끌어다 놓아 열 수 있는 건 .studio.zip뿐입니다. 또는 저장소의 헤들리스 파이프라인으로 창을 띄우지 않고 렌더링할 수도 있습니다: 

npm run headless:export -- launch-screenshots/ out/ --report
# → out/en-US/iphone/01.png … 모든 로케일, 정확한 규격
# → out/layout-report.json + out/layout-summary.json

npm run layout:loop -- launch-screenshots/ out/ --write --max-runs 3
# 렌더 → 보수적 manifest 수정 → 재렌더를 깨끗해질 때까지 반복

에이전트 루프는 이렇습니다: 매니페스트나 캡션을 수정 → 렌더 → layout summary와 PNG 확인 → 안전한 manifest 수정 적용 → 만족할 때까지 반복. 매니페스트 스키마, 파일명 규칙, layout 자동 수정 명령은 docs/project-import.md에 문서화돼 있습니다. 실행 환경 요구사항: npm install까지 마친 저장소 체크아웃(Node, Playwright Chromium). 개발 서버는 스크립트가 직접 띄우고, BASE_URL은 다른 빌드를 가리킬 때만 씁니다.

파일 대신, 앱에 열어 둔 프로젝트를 AI 에이전트가 직접 편집하게 할 수도 있습니다 — MCP 가이드를 참고하세요.

FAQ

프로젝트는 어디에 저장되나요?
내가 가진 .studio.zip 파일 하나에 저장됩니다. 기본 위치는 ~/Documents/Screenshot Studio/이고, 프로젝트와 그 안의 스크린샷이 모두 들어 있어 옮기거나 백업하거나 다른 사람에게 넘길 수 있습니다. 아직 저장하지 않은 작업은 앱 폴더에도 함께 기록해 두었다가, 앱이 예기치 않게 종료된 경우 다시 불러올지 물어봅니다.

비용이 들거나 계정이 필요한가요?
아니요. GitHub에 공개된 MIT 라이선스 오픈소스이고, 백엔드가 아예 없습니다.

어떤 규격으로 내보내나요?
App Store Connect 업로드 슬롯 규격입니다: iPhone 6.9″ (1320×2868), iPhone 6.5″ (1242×2688), iPad 13″ (2064×2752), iPad 11″ (1668×2388) — 실제로 필요한 규격은 사이즈 가이드에서 확인하세요.
